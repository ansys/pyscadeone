Model section items#

ModelElement subclasses#

Each model section item is represented by one of the following classes, which all inherit from ModelElement, thus provide the get_generated_element() method to access the associated generated C element. (see Code section items)

  • ModelArray - Array type definition

  • ModelStruct - Structure type definition

  • ModelStructField - Field within a structure

  • ModelEnum - Enumeration type definition

  • ModelEnumValue - Value within an enumeration

  • ModelVariant - Variant type definition

  • ModelVariantConstructor - Constructor within a variant

  • ModelNamedType - Named type (user-defined type reference)

  • ModelMonoOperator - Monomorphized operator

  • ModelProbesGroup - Group of probes

Model groups#

Some model items can be returned as groups (ModelGroup) of said items. These items are:

  • Flows ModelVariable, found in ModelOperator inputs and outputs, returned as ModelVariablesGroup

  • Probes ModelProbe, found in ModelOperator, ModelMonoOperator, ModelLoopInstance and ModelOperatorInstance, returned as ModelProbesGroup

These groups possess a common identifier: respectively name and path for variables and probes. Both possess an attribute projections which is a list of all their respective items, represented as projections. A projection is a list of strings or integers which represent the location of the item in the group hierarchy. Integers are used for positional (location in current level) and strings are used for labels (element name or sub-group name).

Groups cannot use the method get_generated_element() (it will return None), they must use get_generated_group_elements() instead. However, each of a group’s projections can use the method get_generated_element() normally.

This class provides common functionality for all model elements, including access to their generated code elements through the mapping system.

All model elements that inherit from this class must have an ‘id’ attribute.
